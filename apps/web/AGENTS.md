# Web 模块规则

本文件适用于 `apps/web/`，只能补充根目录规则，不能放宽它。

## 开始前

读取根目录 `AGENTS.md`、`ARCHITECTURE.md`、`CURRENT_STATUS.md` 和当前功能规格。页面、截图和浏览器缓存只能说明前端现象，不能充当最终权限、审计或业务事实。

## 边界

- 跨端契约和零件结构使用 `@fwx/shared` 与 `@fwx/parts-schema`，不得在组件内复制 DTO 或校验规则。
- 登录后的作品以服务端为准；同步失败必须显示可恢复状态，不能悄悄退回本地数据。
- Blockly 使用共享命令中间表示并绑定当前作品；正式路径不得静默载入演示程序。
- Three.js 视觉结果只用于交互和解释，不得呈现为真实飞行、强度或制造证明。
- Three.js、Blockly、导出器等重模块按功能延迟加载；不要把全部 GLB 或第三方公共 CDN 资源塞进首屏。
- 动效默认使用项目已有能力并尊重 `prefers-reduced-motion`；工具页以状态清楚为先，不为展示效果新增整套动效依赖。
- 每个数据界面都要处理加载、空数据、成功、失败、重试、无权限和坏数据状态。
- 未获得文案修改授权时保持现有文字；发现安全承诺与证据不符时报告，不复制该表述。

## 界面文案

- 直接说明页面用途、用户能做的操作和当前状态。使用普通、具体的陈述，不写宣传口号、含糊比喻或夸张的能力承诺。
- 按钮写实际动作；入口说明必须与实际页面一致，共用登录不能描述为独立身份入口。
- 未开放功能、模拟与实机的区别、图纸缺失等影响使用的限制，在对应位置简短说明，不用内部开发代号代替解释。
- 不在官网介绍、正常绘制或自由拼装中重复制造、结构和飞行免责声明；不能仅因使用自制零件就显示警告。功能名称应准确，实际缺失的数据或失败操作在对应位置说明。
- 提示只写当前问题和修改办法，能直接操作时提供入口。同一问题只显示一次；正常、空白及绘制中不在三维区域放常驻说明框，不自动抢焦点。
- 不编造用户评价、获奖、教学效果、加工参数或未来交付时间。用户自行填写的作品、评论与个人资料原文不参与统一改写。
- 用户明确确认的评价及公开授权，记录后按已确认资料执行，不重复要求证明，不擅自替换成说明或占位内容；确认日期和范围见 `CURRENT_STATUS.md`。
- 保留用户明确锁定的区域；首页顶部内容只有用户明确要求修改时才能调整。

## 实现与验证

- 每次界面设计或新增页面先读 [`DESIGN.md`](../../DESIGN.md) 与全站视觉基准 [`docs/design/dji-reference.md`](../../docs/design/dji-reference.md)，再选最接近的已有页面和共享组件；白灰为主体、蓝色为操作点缀，禁止脱离参考另造主题。使用公共字号、字重、字距、间距、色彩和控件规则，不在单页重新引入 MiSans、钉钉进步体或其他展示字体。
- 字体采用 Open Sans 与参考页相同的系统中文回退顺序；首页大型 `FLIGHT / WOOD X` 保留 Montserrat Black 900。后续明确的用户设计要求优先。
- 营销按钮、图片和编辑器控件按各自用途应用圆角；保留开孔/删除红色、Blockly 分类色、木纹及触控操作区域，不为样式相似改变业务交互。
- 用户确认的局部细节只在相应范围生效，更新参考文件中的对应条目；新页面先复用，不强制塞入与功能无关的宣传区块。若参考和旧代码不一致，按文档与用户最新决定核对，不把遗留差异当新默认值。

- 先为可观察行为写失败测试，再改实现。
- 样式和交互必须在真实浏览器验证，不能只依赖 DOM 测试。
- 核心闭环变更至少验证：零件选择或绘制、拼装、Blockly、仿真、保存、重新打开，以及适用的导出路径。
- 检查 `390×844`、`768×1024`、`1440×900`，记录控制台错误和失败网络请求。
- 先运行 Web 目标测试，再运行根目录 `pnpm run harness` 与 `pnpm run ci`。

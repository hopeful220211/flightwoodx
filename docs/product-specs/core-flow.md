## 主线

```text
绘制/选择零件 → 拼装 → Blockly → 视觉仿真 → 保存 → 部分导出
```

六段必须围绕同一个 `DroneDesign` 工作。程序通过 `programId` 与作品绑定；社区、赛事、后台和后续真机适配可以消费作品，但不属于这条最小主线的必经步骤。

机体数据与飞行程序保持分离：零件、连接、二维几何和结构规则属于机体领域；Blockly 只生成 `CommandProgram` IR，由视觉仿真适配器消费。程序可运行不代表实物可飞。

## 目标验收

以下是产品验收目标，不是当前完成声明。

| 环节 | 验收条件 | 最低证据 |
|---|---|---|
| 绘制/选择零件 | 可创建或选择来源明确的官方零件或用户零件；共享契约拒绝坏数据；来源、版本和验证状态不会在后续步骤丢失 | 契约与坏数据测试；用户零件服务端复核；浏览器实际路径 |
| 拼装 | 同一拼装输入形状可承载官方零件和用户零件；作品只保存实例、变换和连接；非法连接不会被静默接受 | 合法/非法连接测试；保存后刷新复验；目标视口人工检查 |
| Blockly | 当前作品只读取和保存自己的程序；有效 XML 编译为版本明确的 IR；损坏输入被拒绝且不覆盖原草稿；正式路径不静默使用 DEMO | Blockly→IR、坏 XML、作品隔离和程序绑定测试；实际编程路径 |
| 视觉仿真 | 只运行当前作品的当前程序；开始、停止、失败和竞态都有确定结果；界面明确标为视觉仿真 | 适配器测试；停止/失败/竞态测试；实际运行路径 |
| 保存 | 游客草稿与登录用户正式记录边界明确；登录用户写入服务端 `DroneDesign`；重试幂等；失败保留本地内容并显式提示；冲突不被静默覆盖 | 契约与 API 的正常、非法、越权、重复和并发测试；保存、刷新、重试及冲突路径 |
| 部分导出 | 只导出已有且来源合格的数据；单位、轮廓、清单和输出可重复；缺少二维源的零件进入明确待补清单 | 几何和导出确定性测试；文件清单检查；真实目标软件检查仅在有制造证据时进行 |

## 端到端通过条件

零件绘制中，每次成功创建图形后立即切回选择工具，并选中新图形；拖拽、Enter 创建以及多边形/自由画完成闭合遵循同一规则。尚未完成、失败或取消的绘制不切换工具。完成闭合后保留画布键盘焦点，可直接用方向键移动新图形。

底部工具栏提供独立的插接口工具，以开口凹槽图标区别普通矩形开孔。从实际木板外边缘向内拖动，自动确定水平或竖直方向，槽宽固定 2 mm；槽底蓝点与箭头说明位置和插入方向。普通切孔不自动成为插接口。新增接口若没有有效开口、损坏槽底或切断木板，则保留原图并说明原因。边缘插接口随零件保存，在拼装器中选择双方接口后自动对齐槽底并垂直摆放；板内槽和普通孔不加入此连接方式。

新建作品必须明确选择按步骤拼装或自由拼装，不预选模式；两种模式均能使用账号中的自制零件。步骤模式保留步骤布局，按当前类别检索我的零件。绘制入口携带原作品和类别，保存后可直接放回原作品，不静默转换模式。自由模式可先独立放置，再用连接零件指定双方接口；画板显示选中零件的接口编号。

连接复用 `activeConnectorId` 与 `attachedTo`，自制端标识为 `joint:<guide-id>`。官方接口从随仓库发布的 GLB 节点生成、比对，不能由客户端伪造；自制端从已验证外轮廓及边缘槽标注派生，使用与渲染一致的中心坐标与米单位。服务端按当前账号取源，核对版本、类别、更新时间和实际对齐。拒绝重复占用、自连接、循环、失效源和缩放后连接；移动连接根时子件跟随，断开时保留当前位置。原无连接草稿保留，不要求补槽；旧官方连接可继续恢复。

底部各工具悬停或获得键盘焦点时显示简短名称，禁用工具也可悬停查看；离开、点击或按 Escape 后收起。选中插接口后，在画布内说明从板边向内拖动；实际外轮廓以红线提示，靠近可起笔边缘时吸附落点并切换十字指针，其他位置使用禁止指针。空画布、无效起点或拖动失败就地显示操作方法，不重复报错、不改变顶部与画布尺寸。悬停标记与实际起笔使用同一范围判定，参考框和内孔不视为入口。

无法生成零件三维预览时，预览区只显示简短原因、修改方法和必要入口，包括实体未连接或被切断、超出参考范围、没有实体、全部被切除及非法轮廓。同一错误不在左右两侧重复显示。已确定来源的错误同时标出原图形，并提供选中入口；不能确定来源时不得随意归责。正常、空画布和未完成绘制不显示右侧说明框，反馈不自动抢焦点。二维内容始终保留，修正或撤销后自动恢复实际预览；不得用旧预览掩盖当前错误。插槽位置错误但木板几何有效时，仍保留木板预览并禁止无效保存。

官网和工具页以功能、当前状态及操作说明为主，不重复制造、结构和飞行免责声明。普通自制件自由摆放不触发设计警告；真正影响当前操作的缺件、来源失效、连接或保存失败保持可见。检查报告先呈现错误和有修改方法的提示，正常项目及数量、暂无数据等信息可展开查看；不以总分概括制造或飞行结论。

一次核心流程验收至少记录：

1. 测试日期、commit、运行环境和执行命令。
2. 从零件入口到导出的连续操作路径，不用 mock、演示回退或占位按钮代替正式数据。
3. 正常、坏输入、断网或服务失败、重复提交和无权限路径。
4. 保存后刷新、重新登录和换设备的结果；多设备冲突协议未实现时必须判为未通过。
5. Chromium `390×844`、`768×1024`、`1440×900`；任务另有浏览器或设备要求时追加实测。
6. 导出内容、缺失来源清单和界面文案与实际证据一致。
7. 相关自动化及 `pnpm run ci` 结果；仓库红灯或任一必经路径未通过时，不得登记为端到端完成。

## 证据边界

- `@fwx/flight-check` 只能证明确定性规则的运行结果，不是物理仿真、适航认证或实飞保证。
- 视觉仿真只能证明指令流程和视觉动作，不预测真实飞行成功率。
- `@fwx/geometry` 只能转换已有合法二维轮廓；GLB/OBJ、界面预览或生成成功不证明可制造。
- 部分导出必须同时说明已导出内容和缺失内容；没有获批二维源、材料、公差、切割参数与真实软件检查时，不能称为加工包。
- 重量、推力、续航、重心、安全阈值和真实飞行结论必须有可追溯硬件实测。没有来源时只能标为占位或估算，不能进入对外结论。
- 页面、路由、RFC、勾选框和本文档本身都不证明实现完成。当前证据只从 [`CURRENT_STATUS.md`](../../CURRENT_STATUS.md) 读取。

## 非目标

- 本规格不定义真实飞行预测、适航、安全认证、材料强度或自动制造判定。
- 本规格不把社区、赛事、成长体系、学校管理或后台作为核心流程完成条件。
- 本规格不定义尚未获批的真机适配器、生产级 SLO 或硬件参数。

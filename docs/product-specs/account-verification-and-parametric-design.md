# 账号验证与参数化设计建议

> 状态：调研建议；验证码注册、身份数据库扩展与参数化机架均未实施。
>
> 更新时间：2026-09-20。
>
> 适用范围：FlightWoodX 国内个人用户注册、可选统计与自制无人机设计。
>
> 替代关系：补充现有账号与隐私实现，不替代 `analytics.md`、共享契约或实际飞行证据。

## 当前实现

已核对 `apps/api/src/models/User.js`、`routes/auth.js`、Web 注册页和统计模块。账号使用邮箱与密码，邮箱格式通过不代表邮箱所有权已验证；目前没有手机身份、验证码接口或验证记录。密码使用现有 bcrypt 哈希，不另建明文密码库。

2026-09-20 公网只读检查 `/api/analytics/config` 返回统计已启用、noticeVersion=1、保留90天。本地隔离测试环境未启用统计。因此本地不出现提示，不代表线上也不出现。

## Cookie 与注册协议

- 必要的登录状态、保存功能，与可选使用统计分开说明；注册同意协议不等于同意统计。
- 正式站首次访问且没有有效选择记录时，显示隐私与 Cookie 提示；选择允许或拒绝，同一账号/浏览器有效期内不反复出现。
- 当前选择最长保存90天。清理浏览器数据、换设备或账号、到期及通知版本变化，会重新判断是否需要询问。
- 未选择或拒绝时不发送可选统计事件，不妨碍正常使用；可在隐私设置撤回。14岁以下不启用可选统计，页面上的年龄勾选不等于监护人验证。
- 注册协议、必要数据说明、可选统计不能合并成一次全部授权。后续若改变处理目的或方式，应另行评估通知和同意；依据个人信息保护法第14—16、31条。[官方法律文本](https://www.samr.gov.cn/wljys/gzzd/art/2023/art_3ef1e889c1e644d4b65b5f5c7f432386.html)

## 建议的用户流程

1. 选择邮箱或手机号，输入地址/号码。
2. 点击发送验证码；界面显示发送结果和重发倒计时，可修改地址。
3. 输入短期有效验证码；服务端核实后获得仅用于此次注册的短期凭证。
4. 设置密码、确认必需协议，提交注册。用户名可在创建账号后修改，减少第一步输入。
5. 以后使用已验证的邮箱或手机号加同一个密码登录；验证码登录可作为另一个入口，不能与注册凭证混用。
6. 在账号设置中绑定第二种联系方式，归属于原账号。换绑、找回密码需要独立验证用途和风控。

建议先上线邮箱验证，再接入国内短信。登录页不可提前显示尚不能发送的验证方式。已有账号补验证，不能把历史填写过的邮箱自动标为已验证。

## 服务开通

**邮箱：**以阿里云邮件推送为例，开通企业账号服务，添加独立发送子域名（如 `notify.flightwoodx.com`），按控制台配置和验证 SPF、DKIM、DMARC 等DNS记录，验证发信地址与额度。服务器使用最小权限凭据发送验证码；密钥不进入前端。先测试投递、垃圾邮件归类、失败回执及重试，再开放注册。[发送域名官方说明](https://help.aliyun.com/zh/direct-mail/user-guide/how-to-configure-sending-domain-names)

**短信：**开通国内短信服务并完成企业认证，申请真实品牌短信签名和验证码模板，审核通过后设置发送额度/费用上限及最小权限凭据。接入服务端发送接口，测试验证码送达、失败提示与限流后再启用手机号入口。签名、模板审核和发送费用取决于服务商及当前申请，不能以代码写完代替服务开通。[模板官方说明](https://help.aliyun.com/zh/sms/user-guide/create-message-templates-1)

## 数据库建议（沿用 MongoDB）

不把邮箱用户和手机用户分成两套账号库。作品和零件继续关联原有用户ID。

| 集合 | 主要字段与约束 |
| --- | --- |
| users | 保留稳定ID、密码哈希、角色及tokenVersion；不在前端决定身份或权限 |
| authIdentities | userId、type=email/phone、规范化后的value、verifiedAt；`(type,value)`唯一索引；手机号使用国际区号规范格式，邮箱按明确一致规则处理 |
| verificationChallenges | 随机challengeId、用途、渠道、收件标识、验证码的带服务端密钥摘要、expiresAt、尝试次数、consumedAt、发送状态；到期清理TTL索引 |
| consentRecords | userId、协议种类与版本、同意时间、渠道；可选统计继续使用现有独立同意记录 |

验证码建议6位、5分钟有效、60秒重发间隔，次数与每日额度由服务端配置。这些是初始建议，不是已上线数值。必须同时做到：

- 按收件人及IP限速、失败次数限制、重发作废旧码、费用熔断；必要时增加人机验证。
- 使用服务端密钥摘要，不能只做低成本的普通哈希；日志不记录明文验证码、完整凭据或密码。
- 验证时检查实际过期时间；TTL清理存在延迟，不能作为是否有效的判断。
- 用原子条件更新消费挑战，拒绝重复及并发重放；注册、登录、重置、绑定的用途不可互换。
- 发送失败明确告知用户。供应商重试有幂等控制，避免多次计费和多条不同验证码。
- 验证凭证一次性、短期有效，并绑定渠道、收件人和用途。最终注册再次校验，在事务内消费凭证并建立唯一身份；唯一索引冲突应返回可恢复错误。
- 不通过未验证邮箱或手机号自动合并账号；绑定到已有账号必须证明当前账号控制权和新联系方式所有权。
- 迁移先查重、备份和补充索引；保留现有用户ID、作品关联与未验证标记，再分批提示补验证。手机号单独注册前，必须同步调整现有User邮箱必填约束和唯一索引，把登录查询迁到已验证身份集合；不能用虚构邮箱填补旧字段。

后续实施必须先在共享包定义发送、验证、注册/登录和绑定契约，再同步API权限、索引迁移、页面和重复/并发测试。本轮没有执行迁移或开通服务。

参考：[OWASP 邮箱验证](https://cheatsheetseries.owasp.org/cheatsheets/Email_Validation_and_Verification_Cheat_Sheet.html)、[OWASP 身份认证](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)。

## 参数化无人机的可行方向

建议做可调尺寸但受范围约束的已验证机架。固定电机/桨叶/电池/主控组合、主要承力路径、桨盘间距、安装孔和插接尺寸；让用户在规定范围内改变保护板、装饰和部分外轮廓。参数变化后重新计算质量、重心、间距和匹配数据，超出已验证范围时不按原组合直接下单。

先选少量实际样机，记录材料、板厚公差、连接强度、实测推力/电流、重心和飞行测试结果，再确定哪些参数范围可交给用户调整。按具体硬件组合组织数据，不用单个通用升力公式代表全部配置。

这能显著提高可制造性和飞行成功率，但软件约束不能保证每架用户自行组装的飞机一定起飞；电池、电机、装配、重心及飞控设置仍影响结果。PX4 的多旋翼配置也包含安装、校准和调参等步骤。[PX4 多旋翼配置](https://docs.px4.io/main/en/config_mc/)

推荐先提供已验证基础机架上的有限定制，稳定后再逐步扩大自定义范围。当前自由绘制、几何预览和保存功能仍是设计工具，不将本建议写成已完成的硬件验证。

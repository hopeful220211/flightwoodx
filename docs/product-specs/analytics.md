## 数据怎样使用

统计回答：用户从哪里进入、是否开始创作、在哪里遇到问题、是否保存、是否回来继续使用。页面访问与真实创作分别计数。事件契约的唯一来源为 `packages/shared/src/analytics.ts`，不从点击文案、任意 DOM 或全量请求自动抓取。

首版没有分析看板或历史留存快照。管理员可读取指定时间段汇总、导出 CSV；后续留存和渠道转化分析基于开始采集后的记录，不能补造之前的月活。

## 事件位置与完成条件

| 操作 | 事件 | 何时记、何时不记 |
|---|---|---|
| 页面与来源 | `page_viewed` | 同意后路由进入；只存页面类别、设备档位及允许的推广标签，不存完整 URL |
| 官网入口 | `home_cta_clicked` | 点击首页四组入口，记录位置和目标 |
| 注册、登录 | `auth_started` / `auth_completed` | 前端发起；成功只由 API 确认 |
| 新建、打开作品 | `design_created` / `design_opened` | 区分显式新建与自动空草稿；新建数不等于有效作品数 |
| 开始编辑 | `design_edit_started` | 实际编辑，不把选择、看图、相机旋转算创作 |
| 草图提交 | `sketch_shape_committed` | 一个完整形状一次；不记录拖动轨迹或每帧坐标 |
| 预览问题 | `sketch_preview_state_changed` | 出现、原因变化、恢复各一次；仍有3D的插槽错误不计预览消失 |
| 拼装 | `assembly_part_added` / `assembly_step_completed` | 实际加件或成功推进步骤；只记官方/自制来源，不传结构内容 |
| 检查 | `assembly_check_completed` | 记录当次现有规则结果，不作为真实飞行证明 |
| 作品与零件保存 | `design_saved` / `custom_part_saved` | API 持久化成功；同内容自动保存不重复增加记录 |
| 本地作品保存 | `local_design_saved` | 显式本地保存完成，与账号保存分开 |
| 程序 | `program_edited` / `program_saved` / `program_bound` | 编辑、API写入、绑定到作品分别确认；不传XML或指令正文 |
| 模拟 | `simulation_run` | 同一运行ID的开始和实际结束；成功、碰撞、错误、主动停止分开，不采集高频遥测 |
| 社区 | `community_published` / `design_remixed` | API 成功创建；重复发布或复用不冒充新结果 |
| 链接 | `community_link_copied` | 剪贴板写入成功，不代表别人已访问 |
| 导出 | `export_prepared` | 文件准备完成，记录可用/缺失数量，不宣称磁盘下载成功 |
| 联系 | `contact_action` | 电话点击或微信复制成功，不上传联系方式 |
| 故障 | `operation_failed` / `app_problem` | 固定操作类别、错误类别；不传异常正文、堆栈、用户名或输入内容 |

`design_saved.change`：`created` 是数据库确认的新建，`edited` 是内容摘要发生变化，`observed` 是已有作品首次被统计观察，不能证明改动。`metadata`、`unchanged` 预留用于明确无内容改动的结果。标题与保存时间不参与内容摘要。首次观察和空草稿不计有效创作。

前端作品事件的 `designId` 是本地稳定ID；服务器 `design_saved.designId` 是数据库ID，并附带通过白名单校验的 `localDesignId`，用于关联同一作品的编辑和保存，不用作品名称关联。

## 指标口径

所有汇总只包含**已同意、未撤回、未过期**的参与者；这不是全站全部用户的普查。

| 返回字段 | 解释 |
|---|---|
| `registeredActiveCreators` | 时间段内有实际编辑、提交形状、添加零件、启动模拟或有效保存的账号去重数 |
| `guestActiveBrowsers` | 同类行为的游客随机标识去重数，不能称为自然人数，也不能直接与账号相加 |
| `uniqueSavedDesigns` | 时间段内成功保存过的非空账号作品去重数，包括已有作品；不是累计作品总数或新增作品数 |
| `uniqueSavedParts` | 时间段内成功保存过的自制零件去重数 |
| `events` / `totalEvents` | 各事件次数和总次数，不等于用户数或作品数 |
| `firstCollectedAt` | 当前尚未过期、未撤回记录中最早接收时间；会随删除移动，不是永久上线日期 |

`from` 包含、`to` 不包含；默认最近30天，可指定不超过90天的窗口。自然月月活需明确传入上海时区该月00:00至下月00:00换算后的ISO时间，不能把最近30天直接称为自然月，也不能累加每日去重数得到月活。

首版授权会在登录、退出或换账号时重置；游客历史不并入新账号。单个页面会话内可关联过程与结果，但不能逐人拼接游客到账号的完整转化。刷新产生新会话；30分钟仅是未发送事件的最大排队时间，不是会话时长定义。清理浏览器数据或重新授权可能产生新的游客标识。

## 隐私与存储

- 默认不采集。用户明确选择并勾选已满14周岁后，服务器发签名授权凭据；年龄勾选不是身份验证。未满14周岁不启用这项可选统计，本轮未建设监护人授权流程。
- 首访使用底部简短横条，按钮为“不允许”和“允许使用统计”，没有“仅必要功能”，不限制绘制、保存等功能。页脚和账号设置链接 `/privacy/settings`，不使用常驻悬浮按钮；撤回即停止入队、取消发送，并删除本次授权事件和摘要；网络失败会显示未删除完成并重试。
- `/privacy` 为公开政策目录，`/privacy/policy`、`cookies`、`data`、`children`、`rights` 分别提供完整隐私政策、同类存储技术说明、信息清单、儿童保护和数据管理说明。登录注册提供文档链接，阅读、登录不等于同意统计。政策阅读页不自动覆盖提示，设置页允许主动选择。
- 同意和拒绝均绑定当前浏览器及身份，最多90天。同身份刷新、页面切换、重开浏览器不重新询问；退出、身份/游客模式切换、清理本站存储、新浏览器/设备、过期或不兼容告知版本重新询问。即使重登原账号也不恢复退出前的授权；不跨设备同步许可。前台恢复、页面切换及事件发送时检查过期。
- 浏览器只持久化授权选择及待删除凭据；行为事件只在内存排队。登录切换和跨标签撤回清空旧上下文。
- 服务器只保存固定字段、内部资源ID和经独立密钥处理的账号/游客标识，不保存姓名、邮箱、手机号、作品名称、形状、程序、完整网址、IP或完整User-Agent。不存在第三方脚本、录屏和设备指纹。
- `AnalyticsConsent`、`AnalyticsEvent`、`AnalyticsRevision` 为独立集合，90天TTL；查询同时过滤过期记录，不依赖Mongo后台TTL扫描时点。业务数据库和现有安全访问日志保持原有职责，不因撤回统计删除作品。
- 撤回针对当前授权，不是账户全部业务数据删除。共用设备应退出账号；重登后重新选择。历史授权/账户整体信息请求走页面联系我们入口。
- 运营方关闭统计开关后，已保存的有效授权仍可在隐私设置撤回和删除；不会因为关闭收集而隐藏撤回入口。开关关闭时不发送事件，允许删除的API与原密钥须保留。

## 接口与可靠性

| 接口 | 权限与用途 |
|---|---|
| `GET /api/analytics/config` | 公开，只返回开关、版本、保留期和环境 |
| `POST /api/analytics/consent` | 明确同意；登录账号由服务端鉴权识别 |
| `POST /api/analytics/events` | 有效授权＋对应身份；每批最多20条，只接受前端白名单事件 |
| `DELETE /api/analytics/consent` | 授权凭据可作为只删除的凭据；退出后仍可重试删除，不能据此读数据 |
| `GET /api/analytics/summary` | 管理员账号＋现有管理员访问密钥；可选from/to/environment |
| `GET /api/analytics/export.csv` | 同上，仅导出汇总，无逐人明细 |

业务请求附 `X-FWX-Analytics-Consent` 和 `X-FWX-Analytics-Session`；API 从已鉴权请求派生身份。客户端不能伪造服务器成功事件。单条事件ID在重试时稳定，同一授权和事件ID有唯一索引；相同ID不同内容拒绝。

前端队列100条，每10秒最多20条，最多3次尝试；页面隐藏使用keepalive，不阻塞编辑。API统计有独立请求体和限流预算，业务成功后的统计用最多100个任务的异步队列。离线超时、关页、队列溢出或统计服务故障可能丢失行为记录，因此财务/作品库存以业务库为准。

快速注册/登录成功时，用切换前的授权和凭证将旧队列最多20条发送一次，不等待返回、不重试，再清空旧状态。撤回和无效凭证重置不发送。服务器内容摘要去重依赖当前单API进程的串行队列；扩展到多个API实例前需补跨实例原子去重。

## 开启与关闭

1. 本轮仅代码与本地验收，不发布、不接触正式数据库。
2. 之后获发布授权时先更新兼容 API 并确认新集合/索引，再发布 Web。旧 Web 不带授权头仍能正常工作；新 Web 遇到旧/关闭API保持不采集。
3. API `.env.example` 提供 `ANALYTICS_ENABLED=false`、独立的 `ANALYTICS_SECRET` 和 `ANALYTICS_EXCLUDED_USER_IDS`。开启需显式设true并通过原私有配置机制提供独立强密钥，不能复用JWT_SECRET或写进Git。关闭时保留统计密钥，以便继续处理撤回请求。
4. 管理员和明确配置的内部测试账号不参与统计。环境由服务器NODE_ENV决定，正式报表默认production，不信任浏览器传入环境；测试只用本地隔离库。
5. Web 可设置 `VITE_ANALYTICS_RELEASE` 记录安全版本标识；不设置则unknown。推广链接只允许 `utm_source` 为 direct/xiaohongshu/bilibili/douyin/wechat/school/search/community/other，`utm_campaign` 为 launch_2026/teacher_pilot/community_share；未知值直接丢弃。没有标签不自动猜成direct。
6. 开启后先用排除的验收账号检查真实流程；正式参与者自主选择后才有实际样本。关闭 `ANALYTICS_ENABLED` 可停止新增采集，不删除作品，也不清除已记录统计。
